# Пакет app

Пакет содержит HTTP-каркас, централизованную конфигурацию и слой данных SQLite v1.
Обработка сообщений покупателей и вызовы LLM пока не реализованы.

| Файл | Ответственность и публичный интерфейс |
| --- | --- |
| `__init__.py` | Обозначает Python-пакет; не запускает приложение |
| `config.py` | `Settings` загружает типизированные настройки из окружения и `.env`; `load_settings()` возвращает их либо возбуждает `ConfigurationError` с именами некорректных полей без значений |
| `schemas.py` | `HealthResponse` определяет JSON-контракт `/health`: единственное поле `status` со значением `ok` |
| `main.py` | `create_app()` создаёт FastAPI; `app` — экземпляр для Uvicorn; startup проверяет настройки, инициализирует SQLite, очищает истёкшие диалоги и сохраняет настройки в `app.state.settings` |
| `assistant.py` | Описание назначения будущей координации сообщений и бизнес-правил; исполняемой логики нет |
| `llm.py` | Описание назначения будущего адаптера DeepSeek и проверки JSON; вызовов API нет |
| `database.py` | Соединения, SQLite v1, проверка исходного регламента, три репозитория и типизированные результаты чтения |

Файлы будущих компонентов `assistant.py` и `llm.py` созданы по уточнению к карточке 06:
полное утверждённое дерево должно присутствовать, а для отложенной логики
разрешены файлы только с описанием назначения. Они не импортируются рабочими
маршрутами и не объявляют фиктивных функций или классов.

Зависимости: `main.py` использует `config.py`, `database.py` и `schemas.py`. Модель ответа
не зависит от конфигурации. Настройки не зависят от HTTP API. При импорте
`app.main` настройки ещё не читаются: проверка выполняется в lifespan до
обслуживания запросов. Настройки и SQLite проверяются до запуска API; ошибки
останавливают старт. Операции SQLite при старте выполняются в пуле потоков,
а не блокируют цикл событий. Глобального соединения с БД нет.

Поток текущего запроса: HTTP `GET /health` → маршрут → `HealthResponse` → JSON.
Настройки и секреты не включаются в ответ или OpenAPI. `create_app()` позволяет
создавать независимые приложения в тестах. На `/health` нет проверок внешних
сервисов: этот endpoint подтверждает только работоспособность процесса API.

`Settings` неизменяемый. `DEEPSEEK_API_KEY` хранится как `SecretStr`, скрывающий
ключ при обычном выводе модели. Значение можно получить явно через
`get_secret_value()`; его нельзя записывать в логи. `load_settings()` заменяет
стандартную ошибку Pydantic на безопасное сообщение. Приоритет источников и
допустимые значения перечислены в корневом README. Загрузка `.env` использует
[Pydantic Settings](https://docs.pydantic.dev/latest/concepts/pydantic_settings/).

## Интерфейс слоя данных

Все компоненты размещены в существующем `database.py`, без ORM и общего
BaseRepository. Репозитории получают соединение, которое создаёт и закрывает
вызывающий код. На HTTP-запрос нужно отдельное соединение в том же рабочем потоке.

| Интерфейс | Результат и ответственность |
| --- | --- |
| `open_database(path)` | Контекст соединения с `foreign_keys=ON`, `busy_timeout=5000`; закрытие при выходе |
| `transaction(connection)` | Короткий `BEGIN IMMEDIATE` с фиксацией либо откатом; вложенные транзакции не поддерживаются |
| `initialize_database(path, ttl_hours=24, *, now=None)` | Атомарное создание v1 либо проверка существующей БД; очистка истёкших диалогов только после успешной проверки |
| `hash_session_token(token)` | SHA-256 непустого токена; исходное значение не записывается в БД |
| `KnowledgeRepository(connection).read()` | Новый `Regulation` из четырёх таблиц с проверкой всех шести исходных фактов; без кеша и подстановок |
| `ConversationRepository(connection, ttl_hours=24).create(*, now=None)` | Пара `(Conversation, token)`; UUID и высокоэнтропийный токен создаются сервером, хранится только хеш |
| `.find_active(session_token_hash, *, now=None)` | Активный `Conversation` либо `None`; точная граница TTL уже считается истечением |
| `.touch(conversation_id, *, now=None)` | Обновление активности непросроченного диалога; `bool`, запрет движения времени назад |
| `.delete(conversation_id)` | Удаление диалога с каскадом сообщений; `bool` |
| `.cleanup_expired(*, now=None)` | Число удалённых диалогов с каскадом сообщений |
| `MessageRepository(connection, ttl_hours=24).append_user_message(session_token_hash, content, *, now=None)` | Один `Message`; проверка сессии, запись и обновление активности одной короткой транзакцией |
| `.append_assistant_message(conversation_id, content, *, now=None)` | Один `Message` отдельной транзакцией для существующего активного диалога; активность не продлевается |
| `.get_history(session_token_hash, *, now=None)` | Кортеж `Message` активного диалога по `created_at, id`; для отсутствующего/истёкшего — пустой кортеж |

Время в публичных методах — `datetime` с часовым поясом. Значение `None`
означает UTC сейчас; перед записью время нормализуется в канонический UTC
`YYYY-MM-DDTHH:MM:SS.ffffffZ`. Наивное время, некорректные UUID/хеши и текст,
пустой после `strip()`, отклоняются. Роли назначаются методами сервера.

`Regulation`, `Product`, `DeliveryPolicy`, `ReturnPolicy`, `Conversation` и
`Message` — неизменяемые типизированные dataclass-результаты. В `Regulation`
доступны `products`, `delivery`, `returns`, `discounts_allowed`. У диалога
есть только хеш токена. Токен из результата `create()` предназначен для будущей
защищённой cookie; его нельзя записывать в логи.

`DatabaseError` сообщает об ошибке версии, структуры или исходного регламента;
инициализация не изменяет такую БД. `SessionUnavailableError` означает
отсутствующую/просроченную сессию или невозможность безопасно обновить активность.
`ValueError` обозначает некорректные параметры методов. Операции репозиториев
могут также сообщать об ошибках `sqlite3.Error`; значения запросов передаются
параметрами, не вставляются в SQL.

В будущем обработчик чата должен вызвать `cleanup_expired()`, затем
`append_user_message()` и получить историю. Транзакция метода завершится до
сетевого вызова DeepSeek. После него обычный ответ сохраняется через
`append_assistant_message()`. При сбое провайдера пользовательское сообщение
остаётся в истории; техническую ошибку нельзя передавать как обычный ответ.
Обёртка внешней транзакции вокруг методов `append_*` не нужна и недопустима.

FastAPI и CLI `python -m scripts.init_db` используют одну инициализацию.
Схема, исходные факты и поток данных описаны в [архитектуре](../docs/architecture.md).

При расширении пакета сохраняется направление зависимостей:
`main → assistant → llm/database/schemas`; `llm → schemas`.
`database` не зависит от ассистента и LLM, `config` предоставляет настройки.
Дополнительные слои и пакеты для этих связей не требуются.
