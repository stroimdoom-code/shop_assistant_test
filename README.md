# Shop Assistant

Python-прототип консультанта интернет-магазина по утверждённому
регламенту. В объёме [карточки 06](https://trello.com/c/eGWxxccv) созданы
рабочий HTTP-каркас, инструменты качества и полное утверждённое дерево.
В объёме [карточки 03](https://trello.com/c/McJ4Vt4A) реализованы SQLite v1,
исходный регламент, репозитории диалогов и сообщений, автоматическая
инициализация при старте и CLI.
По [карточке классификации](https://trello.com/c/k9SxbMts) реализованы строгий
формат тем, промпт и асинхронный адаптер DeepSeek с проверкой JSON и повторами.
По [карточке ответов](https://trello.com/c/tJIbbpKh) реализован `ShopAssistant`:
история, классификация, применение регламента и сохранение ответа.
По [карточке HTTP API](https://trello.com/c/SkNegOY7) реализованы маршруты чата,
анонимная cookie, полная история, безопасные ошибки и сервис последовательной обработки.

Сейчас доступны запуск FastAPI, `GET /health`, централизованная конфигурация,
SQLite с проверкой исходного регламента, автоматические тесты и инструменты качества.
`/health` возвращает
`{"status":"ok"}` и проверяет доступность процесса API. Он не проверяет
доступность DeepSeek и SQLite.

Сценарий доступен через HTTP API и Python-интерфейс `ShopAssistant.respond()`.
По [карточке React-чата](https://trello.com/c/0JlQUnP5) реализован один экран
React/Vite в `web/`; production-сборку раздаёт тот же FastAPI на `/`.
MVP будет только консультировать: оформление заказов, возвратов и платежей,
проверка статусов заказов и авторизация покупателей в его объём не входят.

## Требования и установка

Нужны Python **3.12**, `pip` и доступ к PyPI для установки зависимостей.
Для интерфейса нужны Node.js **20.19+ в ветке 20 или 22.12+** и npm.
Проверено с Node.js 22.20.0 и npm 10.9.3. Node требуется для сборки и разработки,
production-сервером остаётся FastAPI. React/React DOM и Vite зафиксированы
в `web/package.json` и `web/package-lock.json`.
Все команды ниже выполняются в **PowerShell из корня проекта** — папки,
в которой лежат `README.md`, `pyproject.toml`, `.env` и папка `web`.
В текущем рабочем каталоге перейти в неё можно так:

```powershell
Set-Location 'C:\Users\goood\Desktop\project\shop-assistant-test'
```

Если проект перенесён, замените путь на свой. В VS Code можно открыть папку
проекта и выбрать **Терминал → Создать терминал**; проверьте текущую папку
командой `Get-Location`.

### Подготовка при первом запуске

Если окружение и зависимости ещё не установлены, выполните по очереди:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
npm.cmd --prefix web ci
```

Linux/macOS: `python3.12 -m venv .venv`, далее вместо
`.\.venv\Scripts\python.exe` используйте `.venv/bin/python`, а для копирования
настроек — `cp .env.example .env`. Установка только приложения:
`python -m pip install -e .` внутри окружения.

Зависимости приложения и группа `dev` описаны в `pyproject.toml`.
Диапазоны версий допускают обновления; точный состав проверенного окружения
приведён в [отчёте проверок](docs/verification.md).

## Конфигурация

Заполните `DEEPSEEK_API_KEY` в локальном `.env` своим ключом. В `.env.example`
он намеренно пуст: без ключа приложение не запускается. Для локальной проверки
только `/health` можно указать явно демонстрационное значение
`example-local-key-not-real`; оно не позволяет обращаться к провайдеру.
Запуск API, `/health` и инициализация SQLite не обращаются к DeepSeek.
Сетевой запрос к классификатору выполняется при вызове `classify()` или
`ShopAssistant.respond()`, `AssistantService.process()` или отправке сообщения
через HTTP; для него нужен настоящий ключ провайдера. Чтение истории сеть не вызывает.

Настройки читаются из `.env` в **текущем рабочем каталоге** при старте приложения.
Переменные окружения имеют приоритет над файлом; изменения требуют перезапуска.
Неизвестные поля `.env` игнорируются. Ошибка конфигурации перечисляет проблемные
переменные без вывода переданных значений. Ключ хранится как `SecretStr`.

| Переменная | По умолчанию | Назначение и ограничения |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | Нет | Обязательная непустая строка, секрет |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | HTTPS URL без логина и пароля |
| `DEEPSEEK_MODEL` | `deepseek-flash` | Непустой идентификатор модели |
| `DEEPSEEK_TIMEOUT_SECONDS` | `30` | Положительное конечное число, не более 30 секунд |
| `DEEPSEEK_MAX_ATTEMPTS` | `2` | 1–2 попытки на сообщение, включая первую |
| `SQLITE_PATH` | `data/shop-assistant.sqlite3` | Непустой путь к БД; относительный путь от рабочего каталога |
| `CONVERSATION_TTL_HOURS` | `24` | Положительное целое число часов хранения/неактивности |
| `CLASSIFIER_CONTEXT_MESSAGES` | `5` | Неотрицательное целое число предыдущих сообщений для модели; `0` отключает контекст |

При старте создаётся или проверяется SQLite, затем удаляются просроченные
диалоги и каскадно их сообщения. Методы слоя данных проверяют TTL до чтения
истории и принятия сообщений. `ShopAssistant` также вызывает физическую очистку
при обработке запроса; фонового планировщика нет. Адаптер классификации использует
существующие настройки модели, таймаута и числа попыток.
Реальные `.env`, варианты `.env.*`, SQLite-файлы и локальный каталог `data/`
исключены через `.gitignore`; `.env.example` остаётся доступным для Git.

## Обычный запуск чата — один терминал

Это основной способ **открыть и использовать готовый чат**. Сначала выполните
подготовку выше и заполните `DEEPSEEK_API_KEY` в `.env`. Если ключ уже добавлен,
оставьте существующий `.env`; копировать шаблон повторно не нужно.

1. Откройте PowerShell в корне проекта.
2. Соберите интерфейс, затем запустите сервер:

```powershell
npm.cmd --prefix web run build
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

3. Дождитесь сообщения `Application startup complete` и адреса
   `http://127.0.0.1:8000` в терминале.
4. Откройте в браузере **http://127.0.0.1:8000/** — это страница чата.
5. Оставьте терминал с сервером открытым. Для остановки нажмите **Ctrl+C**.

После запуска Uvicorn командная строка не возвращается — это нормально:
сервер работает и ожидает запросы. Другой frontend-сервер для этого режима
не нужен. Python-окружение вручную активировать не требуется.

При следующих запусках, если файлы React не менялись и `web/dist` уже существует,
достаточно только команды Uvicorn. После изменения интерфейса остановите
Uvicorn, выполните `npm.cmd --prefix web run build` и запустите Uvicorn снова.
После изменения `.env` сервер тоже нужно перезапустить.

Дополнительная проверка в **другом терминале** из любой папки:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

Ожидается `status: ok`. `/health` проверяет сервер, а не страницу чата
и не соединение с DeepSeek. Документация API: http://127.0.0.1:8000/docs.
SQLite создаётся и проверяется при старте автоматически; отдельно запускать
`scripts.init_db` для обычного использования не требуется.

## Режим разработки React — два терминала

Этот режим нужен **для изменения интерфейса**: Vite обновляет страницу при
редактировании файлов. Подготовка Python/npm и `.env` та же, что выше.
Production-сборка `web/dist` в этом режиме не нужна.

**Терминал 1 — FastAPI.** Откройте его в корне проекта и выполните:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

**Терминал 2 — Vite.** Создайте ещё один терминал, тоже в корне проекта:

```powershell
npm.cmd --prefix web run dev
```

Откройте **адрес из терминала Vite**, обычно **http://127.0.0.1:5173/**.
В этом режиме страницу открывают на порту Vite, а API работает на **8000**.
Если Vite выберет другой порт, используйте напечатанный им адрес. Оба терминала
должны оставаться открытыми; для остановки нажмите Ctrl+C в каждом.

Proxy Vite перенаправляет `/api` на `http://127.0.0.1:8000`, поэтому запуск
только Vite позволит открыть страницу, но история и отправка работать не будут.
Запуск только FastAPI не показывает текущие изменения React без пересборки.

## Если запуск не получился

| Что видно | Что сделать |
| --- | --- |
| `npm.ps1` нельзя запустить из-за политики выполнения | Используйте `npm.cmd`, как в командах выше; менять политику PowerShell не нужно |
| Не найдена команда `npm.cmd` или `node` | Установите подходящий Node.js вместе с npm, затем заново откройте терминал |
| Не найден `.venv\Scripts\python.exe` | Проверьте папку через `Get-Location` и выполните подготовку Python-окружения |
| `vite` не найден | Из корня выполните `npm.cmd --prefix web ci` |
| Ошибка `EPERM` для системного кеша npm | Из корня выполните `npm.cmd --prefix web ci --cache .venv/npm-cache` |
| На `8000/` ошибка 503, а `/health` работает | Остановите Uvicorn, выполните сборку и запустите Uvicorn снова |
| В dev-режиме страница открылась, но история не загружается | Проверьте, что FastAPI работает в первом терминале именно на порту 8000 |
| Сервер пишет `Проверьте обязательные настройки...` | Проверьте `.env` в корне и перечисленные в ошибке переменные; для чата нужен действительный `DEEPSEEK_API_KEY` |
| Порт 8000 уже занят (`WinError 10048`) | Остановите ранее запущенный сервер через Ctrl+C в его терминале и запустите один экземпляр |

### Как устроен запуск

В PowerShell используется `npm.cmd`, в Linux/macOS — `npm`. Все команды npm
выше используют `--prefix web`, поэтому переходить в папку `web` не требуется.
Если вы уже находитесь в `web`, вернитесь в корень командой `cd ..`.

Vite создаёт `web/dist`; FastAPI отдаёт `/` и `/assets/*`, без перехвата API
и `/health`. Сборка должна быть готова до запуска Uvicorn. `web/dist` и
`web/node_modules` не хранятся в Git, их создают команды установки и сборки.
В Python wheel интерфейс отдельно не упаковывается: инструкции рассчитаны
на запуск из репозитория. Production-режим использует один процесс Uvicorn,
без запущенного Vite. В режиме разработки запросы тоже остаются same-origin;
CORS включать не нужно.

При открытии чат загружает серверную историю. Enter отправляет, Shift+Enter
добавляет строку; пустой ввод не отправляется, длина ограничена 2000 кодовыми
точками Unicode, исходный текст не обрезается по краям. Во время запроса повторная
отправка блокируется. При сбое черновик восстанавливается, POST автоматически не
повторяется, история заново читается с сервера. После успешного POST история
также синхронизируется, включая возможную замену просроченной сессии.
Ошибка чтения истории даёт кнопку повторной загрузки; отправка до успешной
синхронизации блокируется. Сообщения отображаются обычным текстом React,
без HTML/Markdown и локального хранения переписки или cookie.

## HTTP API чата

API работает с того же origin, что и веб-чат; CORS и streaming отключены.
Запускайте Uvicorn с **одним worker**, как в команде выше: блокировки диалогов
находятся в памяти общего `AssistantService`. Один диалог обрабатывается
последовательно, разные диалоги — независимо. Ожидание DeepSeek не держит
соединение или транзакцию SQLite.

| Метод и путь | Вход | Ответ HTTP 200 |
| --- | --- | --- |
| `POST /api/chat/messages` | `{"message":"Сколько стоит X1?"}` | `{"answer":"...","created_at":"2026-11-05T00:00:00Z"}` |
| `GET /api/chat/history` | Cookie при её наличии | `{"messages":[{"role":"user","content":"...","created_at":"2026-11-05T00:00:00Z"}]}` |

Даты приведены как примеры; API возвращает фактическое время сохранения в UTC.
История полная, без пагинации, в хронологическом порядке. Вход содержит только
строку `message`: от 1 до 2000 символов, хотя бы один непробельный символ.
Текст сохраняется без обрезки и нормализации. Любые дополнительные поля,
включая `role`, историю, токен и идентификатор диалога, запрещены.

Пример PowerShell с сохранением cookie (отправка вызывает настоящий DeepSeek):

```powershell
$chatBody = @{ message = 'Сколько стоит X1?' } | ConvertTo-Json -Compress
Invoke-RestMethod http://127.0.0.1:8000/api/chat/messages -Method Post -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($chatBody)) -SessionVariable chatSession
Invoke-RestMethod http://127.0.0.1:8000/api/chat/history -WebSession $chatSession
```

POST создаёт сессию, если действующей cookie нет. Токен передаётся только в
cookie `shop_assistant_session`; SQLite содержит SHA-256-хеш. Атрибуты cookie:
`HttpOnly`, `SameSite=Lax`, `Path=/api/chat`, без `Domain`, `Secure` при HTTPS
и без `Secure` при локальном HTTP. `Max-Age` равен `CONVERSATION_TTL_HOURS * 3600`
и обновляется при отправке сообщения. Неверная или истёкшая cookie заменяется.
GET без действующей сессии возвращает пустую историю, очищает неверную cookie,
не создаёт сессию и не продлевает TTL. JSON не содержит токенов и ID диалога.
Ответы чата имеют `Cache-Control: no-store`.

Все ошибки имеют формат `{"error":{"code":"...","message":"..."}}`:

| HTTP | `code` | Причина |
| --- | --- | --- |
| 422 | `invalid_request` | Неверный JSON, тип, длина, пустой текст или лишние поля |
| 503 | `service_unavailable` | Недоступность провайдера, SQLite или сессии во время обработки |
| 504 | `request_timeout` | Исчерпание попыток после таймаута |
| 500 | `internal_error` | Непредвиденная внутренняя ошибка |

Внутренние исключения, SQL, ключи и исходные данные ошибки клиенту не передаются.
Если вопрос сохранён до сбоя, он остаётся в истории; технический ответ не
записывается. Cookie новой сессии сохраняется и в ответе с ошибкой, чтобы клиент
мог прочитать эту историю. API не вычисляет факты и не сохраняет сообщения
повторно: весь сценарий выполняет сервис ассистента.

## Инициализация SQLite

Из корня проекта, после настройки `.env`:

```powershell
.\.venv\Scripts\python.exe -m scripts.init_db
```

CLI и запуск FastAPI вызывают одну функцию `initialize_database()`. Для пустой
БД с версией 0 создаются родительский каталог, файл SQLite, шесть таблиц, два
явных индекса и четыре начальные записи регламента. Схема, данные и версия 1
фиксируются одной транзакцией. Начальная история пустая. CLI использует общую
конфигурацию, поэтому `DEEPSEEK_API_KEY` также должен быть заполнен; сетевых
вызовов провайдера при инициализации нет.

Повторный запуск проверяет существующую структуру и **все шесть исходных фактов**.
X1 должен стоить 2490 ₽ и быть в наличии, скидки запрещены, условия доставки,
обычного возврата и экспертизы должны оставаться исходными. Дополнительные
корректные товары допустимы. При отсутствии или изменении обязательного факта
инициализация и старт API останавливаются с понятной ошибкой; БД не исправляется,
не дозаполняется и не очищается. Неподдерживаемая версия и непустая схема с
версией 0 также приводят к отказу без сброса данных. CLI возвращает код 1
при ошибке и 0 при успехе.

После успешной проверки удаляются только просроченные диалоги и их сообщения.
Редактирование регламента и цены, административный интерфейс и журнал изменений
регламента исключены из MVP. Структура и семантика данных описаны в
[архитектуре](docs/architecture.md), интерфейсы — в [документации app](app/README.md).

## Обработка сообщения и ответ

Перед вызовом сценария SQLite должна быть инициализирована, а анонимный диалог
создан существующим `ConversationRepository`. HTTP-маршрут получает
токен из защищённой cookie и передаёт его хеш в `AssistantService`. Для прямого
совместимого Python-вызова внутри вызывающей
coroutine:

```python
from app.assistant import ShopAssistant
from app.config import load_settings
from app.database import hash_session_token

assistant = ShopAssistant(load_settings())
reply = await assistant.respond(hash_session_token(session_token), message)
```

`session_token` и `message` здесь — значения, уже полученные вызывающим кодом.
Сценарий проверяет сессию и читает предыдущую серверную историю. До пяти
предыдущих сообщений по умолчанию передаются в хронологическом порядке;
новый запрос передаётся отдельно и в контексте не дублируется. Лимит задаётся
`CLASSIFIER_CONTEXT_MESSAGES`; при `0` история модели не передаётся.

Запрос пользователя и активность фиксируются одной короткой транзакцией.
DeepSeek вызывается после её завершения. Python читает регламент SQLite,
составляет ответ из готовых фраз и сохраняет его отдельно. Известные и
неизвестные части ответа остаются в порядке запроса, уточняющий вопрос — один.
Скидки не предоставляются и сниженная цена не вычисляется. При браке не
применяются автоматически сроки обычного возврата. Для вскрытого товара
на 16-й день без сведений о браке объясняется истечение срока обычного возврата
и задаётся вопрос о неисправности.

При сбое DeepSeek или SQLite возвращается «Сейчас не могу обработать запрос.
Попробуйте ещё раз чуть позже». Эта фраза не попадает в историю. Если запрос
пользователя уже записан, он сохраняется; цены и условия из памяти не подставляются.
Отсутствующая/истёкшая сессия также не продолжается и не вызывает DeepSeek.
Создание и замена сессии реализованы в HTTP API. Невалидный текст или
формат хеша вызывают `ValueError` до классификации. Подробности — в
[документации app](app/README.md).

## Классификация

`DeepSeekClassifier` из `app/llm.py` принимает сообщение и переданный сервером
недавний контекст. Возвращает все темы с деталями через `ClassificationResult`,
не применяя бизнес-правила и не формируя ответ. Поля и пример использования
описаны в [документации app](app/README.md). HTTPX2 включён в зависимости приложения.

В теме товара `requested_info` сохраняет все запрошенные сведения: цену,
наличие и характеристики с названиями из вопроса. Например, цена и шумоподавление
передаются двумя пунктами. `app/assistant.py` проверяет сведения в регламенте
и сообщает об их отсутствии. Промпт хранится только в `app/prompts/classifier.md`, включён
в wheel и загружается как ресурс пакета; внешний каталог промптов для классификации
после установки не требуется.

Пробный вызов из корня проекта после заполнения настоящего ключа в `.env`:

```powershell
.\.venv\Scripts\python.exe -c "import asyncio; from app.config import load_settings; from app.llm import DeepSeekClassifier; result = asyncio.run(DeepSeekClassifier(load_settings()).classify('Сколько стоят X1 и когда доставите?')); print(result.model_dump_json(indent=2))"
```

Этот вызов обращается к реальному API. Автоматические тесты используют подмену
HTTP-транспорта и не обращаются к DeepSeek. Фактический результат пробного вызова
и статус его выполнения отражаются в [отчёте](docs/verification.md).

## Проверки качества

Используйте интерпретатор созданного окружения. Ниже `python` означает
`.\.venv\Scripts\python.exe` в PowerShell или `.venv/bin/python` в Linux/macOS.

| Команда | Что проверяет |
| --- | --- |
| `python -m ruff check .` | Ошибки кода, импорты, аннотации и Google Style docstrings |
| `python -m ruff format --check .` | Соответствие форматированию Ruff |
| `python -m mypy` | Строгую типизацию `app/`, `scripts/` и `tests/` |
| `python -m bandit -c pyproject.toml -r app scripts` | Проблемы безопасности приложения и скриптов; без отключения правил |
| `python -m pytest` | Изолированные тесты классификации, SQLite, API и конфигурации |
| `python -m pytest --cov --cov-report=term-missing --cov-report=xml` | Покрытие кода и ветвей, порог 90%; создаёт игнорируемый `coverage.xml` |
| `python -m pip_audit --skip-editable --timeout 30 --cache-dir .venv/pip-audit-cache` | Известные уязвимости установленных зависимостей приложения и инструментов |
| `python -m pip check` | Совместимость установленных зависимостей |

Для форматирования с записью: `python -m ruff format .`.
Конфигурация Ruff, mypy, Bandit, pytest и coverage находится в `pyproject.toml`.
`pip-audit` включён в группу `dev`; его параметры задаются командой CLI,
поскольку инструмент не читает секцию `[tool.pip-audit]`.
`--skip-editable` пропускает только локальный пакет `shop-assistant`,
который не опубликован на PyPI, сохраняя проверку его установленных зависимостей.
Для аудита нужен сетевой доступ к сервису уязвимостей PyPI. Ошибка сети
не означает успешную проверку. Исключения для уязвимостей не заданы.
Кеш аудита размещается внутри `.venv`, чтобы проверка не требовала записи
в пользовательские каталоги вне проекта.
Описание CLI: [официальная документация pip-audit](https://github.com/pypa/pip-audit).

Тесты не используют настоящие ключи и не обращаются к DeepSeek. Каждый тест
работает в отдельном временном каталоге без пользовательского `.env`.
Тесты проверяют настройки, контракт `/health`, автоматическую инициализацию,
шесть исходных фактов, ограничения схемы, откат, сохранность БД при ошибке,
хеширование токенов, изоляцию истории, порядок сообщений, точную границу TTL,
каскадное удаление и CLI. Сценарий ответа проверяется с временной SQLite и
подменой классификатора, включая ошибки хранения, историю и запрет скидок.
Классификация проверяется подменой провайдера:
строгая схема, контекст, формат запроса, таймаут, ограниченные повторы и безопасные
ошибки. Контрольные вопросы про заказ 1842, возврат на 16-й день и скидку 20%
проверены на Python-сценарии с подменой классификатора. Это не фактические ответы
DeepSeek и не завершённая демонстрация браузерного прототипа.

Локальные `.venv/`, кеши и отчёты покрытия не являются исходными файлами.

`test_config.py` и `test_main.py` обеспечивают изоляцию и проверки работающего
каркаса; Markdown-файлы документируют пакет и фактические результаты.
`database.py`, `scripts/init_db.py` и `test_database.py` реализованы по карточке 03.
`llm.py`, модели `schemas.py`, `app/prompts/classifier.md` и тесты классификации
в `test_assistant.py` реализованы по карточке DeepSeek. В `assistant.py`
реализован сценарий ответов, а в `test_assistant.py` и `test_security.py` —
его проверки по регламенту и программному запрету скидок. `prompts/system.md`
пока содержит описание назначения. В `web/` реализован единственный React-чат,
старые `web/app.js` и `web/style.css` удалены после переноса в `src/`.

Связи модулей и запланированный поток обработки описаны в
[архитектуре](docs/architecture.md), интерфейсы существующего пакета — в
[документации app](app/README.md), фактические результаты — в
[отчёте проверок](docs/verification.md).
