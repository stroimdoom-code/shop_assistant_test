# Shop Assistant

Каркас Python-прототипа консультанта интернет-магазина по утверждённому
регламенту. В объёме [карточки 06](https://trello.com/c/eGWxxccv) созданы
рабочий HTTP-каркас, инструменты качества и полное утверждённое дерево.
В объёме [карточки 03](https://trello.com/c/McJ4Vt4A) реализованы SQLite v1,
исходный регламент, репозитории диалогов и сообщений, автоматическая
инициализация при старте и CLI.

Сейчас доступны запуск FastAPI, `GET /health`, централизованная конфигурация,
SQLite с проверкой исходного регламента, автоматические тесты и инструменты качества.
`/health` возвращает
`{"status":"ok"}` и проверяет доступность процесса API. Он не проверяет
доступность DeepSeek и SQLite.

Обработка сообщений, вызовы DeepSeek, веб-чат, cookie и системные промпты
реализуются отдельными карточками. Хранение диалогов уже работает в слое данных;
маршрут чата пока отсутствует. Каркас не отвечает на вопросы покупателей.
MVP будет только консультировать: оформление заказов, возвратов и платежей,
проверка статусов заказов и авторизация покупателей в его объём не входят.

## Требования и установка

Нужны Python **3.12**, `pip` и доступ к PyPI для установки зависимостей.
Команды выполняются из корня проекта. PowerShell, без активации окружения:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

Linux/macOS: `python3.12 -m venv .venv`, далее вместо
`.\.venv\Scripts\python.exe` используйте `.venv/bin/python`, а для копирования
настроек — `cp .env.example .env`. Установка только приложения:
`python -m pip install -e .` внутри окружения.

Зависимости приложения и группа `dev` описаны в `pyproject.toml`.
Диапазоны версий допускают обновления; точный состав проверенного окружения
приведён в [отчёте проверок](docs/verification.md).

## Конфигурация

Заполните `DEEPSEEK_API_KEY` в локальном `.env` своим ключом. В `.env.example`
он намеренно пуст: без ключа приложение не запускается. Для локальной проверки
только `/health` можно указать явно демонстрационное значение
`example-local-key-not-real`; оно не позволяет обращаться к провайдеру.
Каркас вообще не выполняет сетевых запросов к DeepSeek и не проверяет ключ у него.

Настройки читаются из `.env` в **текущем рабочем каталоге** при старте приложения.
Переменные окружения имеют приоритет над файлом; изменения требуют перезапуска.
Неизвестные поля `.env` игнорируются. Ошибка конфигурации перечисляет проблемные
переменные без вывода переданных значений. Ключ хранится как `SecretStr`.

| Переменная | По умолчанию | Назначение и ограничения |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | Нет | Обязательная непустая строка, секрет |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | HTTPS URL без логина и пароля |
| `DEEPSEEK_MODEL` | `deepseek-flash` | Непустой идентификатор модели |
| `DEEPSEEK_TIMEOUT_SECONDS` | `30` | Положительное конечное число, не более 30 секунд |
| `DEEPSEEK_MAX_ATTEMPTS` | `2` | 1–2 попытки на сообщение, включая первую |
| `SQLITE_PATH` | `data/shop-assistant.sqlite3` | Непустой путь к БД; относительный путь от рабочего каталога |
| `CONVERSATION_TTL_HOURS` | `24` | Положительное целое число часов хранения/неактивности |

При старте создаётся или проверяется SQLite, затем удаляются просроченные
диалоги и каскадно их сообщения. Методы слоя данных проверяют TTL до чтения
истории и принятия сообщений. Будущий маршрут чата должен также вызывать
физическую очистку; фонового планировщика нет. Вызовы LLM и повторы пока отсутствуют.
Реальные `.env`, варианты `.env.*`, SQLite-файлы и локальный каталог `data/`
исключены через `.gitignore`; `.env.example` остаётся доступным для Git.

## Запуск

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В другом терминале:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

Ожидается HTTP 200 и `{"status":"ok"}`. OpenAPI доступна по `/openapi.json`,
интерактивная документация — по `/docs`. Некорректная конфигурация прерывает
старт до обслуживания запросов с сообщением `Проверьте обязательные настройки
и допустимые значения: ...`.

## Инициализация SQLite

Из корня проекта, после настройки `.env`:

```powershell
.\.venv\Scripts\python.exe -m scripts.init_db
```

CLI и запуск FastAPI вызывают одну функцию `initialize_database()`. Для пустой
БД с версией 0 создаются родительский каталог, файл SQLite, шесть таблиц, два
явных индекса и четыре начальные записи регламента. Схема, данные и версия 1
фиксируются одной транзакцией. Начальная история пустая. CLI использует общую
конфигурацию, поэтому `DEEPSEEK_API_KEY` также должен быть заполнен; сетевых
вызовов провайдера при инициализации нет.

Повторный запуск проверяет существующую структуру и **все шесть исходных фактов**.
X1 должен стоить 2490 ₽ и быть в наличии, скидки запрещены, условия доставки,
обычного возврата и экспертизы должны оставаться исходными. Дополнительные
корректные товары допустимы. При отсутствии или изменении обязательного факта
инициализация и старт API останавливаются с понятной ошибкой; БД не исправляется,
не дозаполняется и не очищается. Неподдерживаемая версия и непустая схема с
версией 0 также приводят к отказу без сброса данных. CLI возвращает код 1
при ошибке и 0 при успехе.

После успешной проверки удаляются только просроченные диалоги и их сообщения.
Редактирование регламента и цены, административный интерфейс и журнал изменений
регламента исключены из MVP. Структура и семантика данных описаны в
[архитектуре](docs/architecture.md), интерфейсы — в [документации app](app/README.md).

## Проверки качества

Используйте интерпретатор созданного окружения. Ниже `python` означает
`.\.venv\Scripts\python.exe` в PowerShell или `.venv/bin/python` в Linux/macOS.

| Команда | Что проверяет |
| --- | --- |
| `python -m ruff check .` | Ошибки кода, импорты, аннотации и Google Style docstrings |
| `python -m ruff format --check .` | Соответствие форматированию Ruff |
| `python -m mypy` | Строгую типизацию `app/`, `scripts/` и `tests/` |
| `python -m bandit -c pyproject.toml -r app scripts` | Проблемы безопасности приложения и скриптов; без отключения правил |
| `python -m pytest` | Изолированные тесты SQLite, API и конфигурации |
| `python -m pytest --cov --cov-report=term-missing --cov-report=xml` | Покрытие кода и ветвей, порог 90%; создаёт игнорируемый `coverage.xml` |
| `python -m pip_audit --skip-editable --timeout 30 --cache-dir .venv/pip-audit-cache` | Известные уязвимости установленных зависимостей приложения и инструментов |
| `python -m pip check` | Совместимость установленных зависимостей |

Для форматирования с записью: `python -m ruff format .`.
Конфигурация Ruff, mypy, Bandit, pytest и coverage находится в `pyproject.toml`.
`pip-audit` включён в группу `dev`; его параметры задаются командой CLI,
поскольку инструмент не читает секцию `[tool.pip-audit]`.
`--skip-editable` пропускает только локальный пакет `shop-assistant`,
который не опубликован на PyPI, сохраняя проверку его установленных зависимостей.
Для аудита нужен сетевой доступ к сервису уязвимостей PyPI. Ошибка сети
не означает успешную проверку. Исключения для уязвимостей не заданы.
Кеш аудита размещается внутри `.venv`, чтобы проверка не требовала записи
в пользовательские каталоги вне проекта.
Описание CLI: [официальная документация pip-audit](https://github.com/pypa/pip-audit).

Тесты не используют настоящие ключи и не обращаются к DeepSeek. Каждый тест
работает в отдельном временном каталоге без пользовательского `.env`.
Тесты проверяют настройки, контракт `/health`, автоматическую инициализацию,
шесть исходных фактов, ограничения схемы, откат, сохранность БД при ошибке,
хеширование токенов, изоляцию истории, порядок сообщений, точную границу TTL,
каскадное удаление и CLI. Три краш-теста ассистента ещё не выполняются.

Локальные `.venv/`, кеши и отчёты покрытия не являются исходными файлами.
Все пути утверждённого дерева созданы. Дополнительные `conftest.py`,
`test_config.py` и `test_main.py` обеспечивают изоляцию и проверки работающего
каркаса; Markdown-файлы документируют пакет и фактические результаты.
`database.py`, `scripts/init_db.py` и `test_database.py` реализованы по карточке 03.
`assistant.py`, `llm.py`, файлы `prompts/`, `web/`, `test_assistant.py`
и `test_security.py` содержат только описания назначения, как ранее разрешено
пользователем. Файлы будущих тестов не учитываются как выполненные сценарии.
Веб-чат не подключён к API.

Связи модулей и запланированный поток обработки описаны в
[архитектуре](docs/architecture.md), интерфейсы существующего пакета — в
[документации app](app/README.md), фактические результаты — в
[отчёте проверок](docs/verification.md).
